# 原文分類 / 要約SOAP

「02 文字起こしと話者を確認」の「SOAPの作成方法」で選択する。
初期値は従来の「原文分類」。どちらも確認した会話を既存LLM-JP APIへ送信する。
基本情報（患者ID・診察日時・担当医・施設名）は送信しない。

| 方式 | モデルの出力 | 帳票の本文 |
|---|---|---|
| 原文分類 | 発話IDをS/O/A/P/要確認へ分類 | 修正済みの原文をそのまま掲載 |
| 要約SOAP | 簡潔な要約と根拠発話ID、省略候補 | 要約だけを掲載。会話原文・省略候補は添付しない |

要約後、各欄の「要約の根拠となる原文を確認」を展開して照合する。
省略候補があれば一覧を初期状態で展開して表示する。必要な情報が省略されていた場合は、
SOAP本文の編集で戻してから医師確認を行う。印刷は3種類の既存テンプレートを利用する。
要確認・未分類欄は要約でも印刷へ含める。コピーも編集した要約本文を使用する。
作成方法を変更すると古い結果を破棄し、会話確認をやり直して再生成する。
処理中に方式を変更した場合の遅延応答は表示しない。

## 要約の指示と機械検査

モデルには、原文にない診断・所見・治療・薬剤・用量を加えず、薬剤名・数値・単位・
否定・時系列・不確実性を保持するよう指示する。患者の推測を医師の診断に変えない。

- 根拠IDが実在すること、各入力IDが要約または省略候補で説明されていることを検証。
- O/A/Pの根拠は医師だけ、話者不明の根拠は要確認だけに限定。
- 数値と一部の単位の表記をNFKC正規化後に照合。根拠にない数値の追加や、原文の数値の
  欠落を拒否。単位換算・丸めも許可しない保守的な検査で、正しい言い換えを拒否する場合もある。
- 独立した挨拶・つなぎ言葉は限定リストのみ省略可。重複候補は同じ話者・同じ本文で、
  根拠に残した発話への参照を必須とする。はい・いいえを不要として省略することは認めない。
- 長さ・JSON項目・根拠形式が不正な結果は表示せず、原文分類へ自動切替もしない。

これらは事実一致や医学的正しさを証明する検査ではない。同じ数値を別の検査や時刻へ
結び付ける誤り、薬剤名の誤記、否定の逆転、重要事項の要約漏れなどを完全には検出できない。
根拠の発話に言及していても、その全文の意味を保持したとは限らない。
挨拶・重複の省略も診療文脈での妥当性を保証しない。医師が根拠・省略候補を含めて確認し、
必要な修正後に印刷・コピーを行う。生成上限は要約8192、原文分類4096トークン。
モデルへの指示だけでは要約の品質は保証できず、実モデルでの検証が必要。

## データと配置

DBやブラウザ永続保存は追加しない。既存APIへ送信する会話本文・生成結果には、
API側のログ設定が適用される。表示中の根拠と省略候補は消去・ログアウト・再読み込みで消える。
開いた印刷画面やコピー/PDF保存先は別途管理する。

テンプレート機能と同じ静的Web変更。EC2で対象ブランチを取得し、
`sudo sh scripts/install-static.sh` を実行してブラウザを再読み込みする。
Docker再ビルド・Apache再起動は不要。詳細は [帳票の配置手順](print-templates.md) を参照。

## 内容から話者候補を推定する

「不明な話者の候補を推定」は、ログインとLLM-JPへの会話送信同意後に利用できる。
会話全体の文脈をLLMへ送り、「不明」の発話だけに医師・患者・家族・不明の候補を仮入力する。
すでに手動設定した役割は上書きしない。根拠不足や複数人の混在は不明のままにするよう指示する。
候補のID・役割・対象件数を検査し、不正な応答は一括して適用しない。

これは内容による推測であり、音声による話者分離や本人識別ではない。役割を正しく推定できた
保証はない。患者が医師の説明を引用した発話、医師による患者の訴えの要約、短い相づちは
特に誤り得る。誰が話したかは原音・診察内容と照合する必要がある。

候補には「内容からの候補（未確認）」と表示する。必要なら各発話のプルダウンを修正し、
「文字起こしと話者を原音・診察内容と照合」にチェックしてからSOAPを生成する。
推定後も自動で会話確認チェックを入れたり、SOAPを生成・印刷したりしない。
候補を再推定したい発話は「不明」へ戻す。既存SOAP結果は候補推定時に破棄する。
消去・会話編集・方式変更後の遅延候補は適用しない。患者ID等の帳票基本情報は送信しない。
