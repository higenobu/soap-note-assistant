# 原文を分類してから、確認済み区分ごとに要約する

「SOAPの作成方法」は「原文分類」または「分類後に要約SOAP」を選ぶ。
どちらも最初のモデル呼び出しでは、発話を言い換えずSOAP区分へ分類する。
要約を選んでも、会話全体を直接要約することはない。

## 操作

1. 文字起こしと話者を原音・診察内容と照合する。内容からの話者候補は未確認の推測なので、
   必要に応じてプルダウンで修正する。LLM-JPへの会話送信同意も確認する。
2. 作成方法を選択し、「原文をSOAPに分類」を押す。
3. 「03 原文の分類を確認・修正」で発話ごとの原文と分類先を確認する。
   プルダウンでS/O/A/P/要確認へ修正できる。O/A/Pは医師の発話だけ、話者不明は要確認に限定。
   複数区分が混ざる場合は要確認に残すか、元の会話で発話を分割して再分類する。
4. 挨拶・相づち等を帳票へ掲載しない場合は、人が内容を見て「省略（手動で確認）」を選ぶ。
   診療に必要な情報まで省略していないか確認する。分類・省略対象の確認チェックを入れる。
5. 「分類後に要約SOAP」を選んだ場合は「確認した分類から要約」を押す。
6. 「04 SOAP下書きを編集・確認」で、表示した確認済み原文と要約を照合する。
   必要な編集を行い、医師確認後に「05 表示・印刷テンプレート」から印刷・PDF保存する。

「原文分類」は、分類確認後にそのまま原文の下書きを利用できる。
原文分類から要約へ切り替えても分類先は保持し、再確認してから要約へ進める。
要約から原文分類へ戻す場合も再分類のAPI呼び出しは不要。

## 区分別の要約と検証

要約時は空でないS/O/A/Pの独立プロンプトを作り、`POST /llmjp/batch` へ1回で送信する。
Sの要約には確認済みSの発話だけ、Pには確認済みPだけを送る。患者ID等の帳票基本情報は
送信しない。本文の入っていない区分のAPI呼び出しは省く。要確認区分はモデルに自由要約させず、
話者付きの原文を保持する。バッチAPIは内部で各プロンプトを順番に生成するため、通信は1回でも最大4回の推論を行う。GPUでの並列生成を意味せず、一括要約より処理時間が長くなる場合がある。

- バッチ応答の件数と、各結果の `prompt` が送信したプロンプトに一致することを照合する。対応が不明な応答は採用しない。
- 各区分の要約は `items` と `omitted` のJSONで受け取る。他区分のIDは根拠として拒否する。
- 対象区分の全発話IDが、根拠IDまたは省略候補に含まれることを検証。不足時はIDを表示する。
- 数値と一部の単位の表記追加・欠落をNFKC正規化後に照合する。換算・丸めを許可しない
  保守的な検査であり、意味的に正しい言い換えも拒否する場合がある。
- モデルが省略できるのは限定リストの独立した挨拶・つなぎ言葉と、同じ話者・本文の重複のみ。
  「はい」「いいえ」は機械的に省略しない。人が確認して選んだ省略対象は別途原文付きで保持する。
- 要約の区分はアプリが固定する。モデルにS/O/A/P間の移動を行わせない。
- いずれかの要約が失敗した場合は、途中結果を最終下書きとして表示しない。
  原文分類は保持するので、確認して再試行するか、原文分類表示へ戻せる。

これらは要約の意味、医学的な正しさ、薬剤名・否定・時系列の完全な保持を保証しない。
「〜のようだ」を診断へ断定する、同じ区分の別の症状と数値を取り違える、引用・伝聞を
所見と誤解する、といった誤りは残り得る。指示だけで防げたとは扱わず、医師が原文と照合する。
分類自体もモデルが誤る可能性がある。発話ID・役割が不正な原文分類は採用しない。
分類と各区分の要約の生成上限はそれぞれ4096トークン。既存APIの `prompts: list[str]`、応答の `results` 配列（各項目の `prompt` / `answer`）を利用する。バッチAPIが未配置の場合は404となるため、API側の配置を確認する。

## 編集・承認の扱い

- 分類先・手動省略を変更すると分類確認と要約・医師確認を解除する。
- 元の会話本文・話者の変更、消去、ログアウトでは原文分類も破棄し、最初から確認し直す。
- 要約処理中の分類変更や消去は待機を中止する。遅れて返った古い結果は表示しない。送信済みのサーバー処理は完了まで続く場合がある。
- 本文や帳票基本情報の編集では医師確認を解除する。
- 要約の根拠原文と省略した原文は画面で照合でき、要約帳票へは添付しない。
  要確認欄は帳票へ残す。コピーも現在の下書きを使い、作成方法を明示する。

## 内容から話者候補を推定する

「不明な話者の候補を推定」は、ログインと会話送信同意後に利用できる。
会話全体をLLMへ送り、「不明」の発話だけに医師・患者・家族・不明の候補を仮入力する。
手動設定した役割は上書きしない。対象ID・役割・件数が不正な応答は適用しない。
音声による話者分離・本人識別ではないため、引用や短い相づち等は特に誤り得る。
候補を原音と照合し、人が会話確認チェックを入れてから分類へ進む。
候補を再推定したい発話は「不明」へ戻す。推定後に分類・要約・印刷を自動実行しない。

## 保存・配置

DBやブラウザ永続保存は追加しない。既存APIへ送信する本文・応答には、API側のログ設定が
適用される。画面の原文・要約・分類先・省略対象は消去・ログアウト・再読み込みで消える。
開いた印刷画面やコピー/PDF保存先は別途管理する。

静的Web変更のためDocker再ビルド・Apache再起動は不要。EC2で対象ブランチを取得し、
`sudo sh scripts/install-static.sh` を実行してブラウザを再読み込みする。
[帳票の配置手順](print-templates.md)を参照。
